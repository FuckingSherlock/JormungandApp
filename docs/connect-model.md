# Модель подключения: источники, профили, цепочки

Что из макета (`design/src/js/`) нужно перенести в логику приложения. Макет — эталон
поведения; этот файл — его описание для бэка (Dart-сервисы + сборка конфига sing-box).
Обновлять при каждом изменении логики в макете.

---

## Сущности

| Сущность | Поля (макет) | Смысл |
|---|---|---|
| **Source** | `kind: sub \| node`, `enabled`, `nodes[]`, `gone[]`, `offNodes[]`, `disabledNodes[]`, `updateInterval`, `inAuto` | Подписка (`sub`) или ручной набор серверов (`node`). Живёт на вкладке Nodes. |
| **Node** | `id`, `protocol`, `address`, `port`, креды, `flag`, `name` | Один сервер (outbound sing-box). |
| **Profile** | `sources[]`, `nodes[]` (`sid::nid`), `inAuto` | Режим «Профили»: набор целых источников и/или отдельных нод. |
| **Chain** | `inId`, `outId`, `inOff[]`, `outOff[]`, `exitMode`, `exitOrder[]`, `inAuto` | Вход (первый хоп) → выход. Концы — «юниты» активного режима. |

`sid::nid` — ключ ноды внутри источника (в макете `refKey`).

## Идентичность ноды

`node.id` = идентичность **сервера**, а не позиция в списке:
`sha256(protocol + address + port + identity)` — тот же ключ, что для дедупликации
(см. `subscription-parsing.md` → «Дедупликация нод»). Имя в ключ не входит.

Все настройки ссылаются на `id`: `offNodes`, `disabledNodes`, `profile.nodes`, `chain.inOff/outOff/exitOrder`.
Поэтому провайдер может перетасовать или переименовать ноды — выбор пользователя не съедет.

## Пропавшие ноды (`gone`) — кэш выбора

При обновлении подписки нода, которой больше нет в ответе, **не удаляется**, а
переносится в `source.gone[]` с `goneAt`. Настройки, которые на неё ссылаются, не трогаются.

- Нода вернулась в следующем обновлении (тот же `id`) → переезжает обратно в `nodes[]`
  и сразу оказывается с прежней галочкой и на прежнем месте в приоритете выхода.
- Новая нода (раньше не было) → включена, в приоритете выхода — в конце.
- В UI пропавшие ноды показываются свёрнутым блоком «Unavailable · N» везде, где есть
  список нод (Nodes, настройка источника, редактор профиля, редактор цепочки), только
  для чтения, с сохранённым состоянием галочки.
- **Срок хранения — 15 дней на каждый сервер отдельно** (`GONE_KEEP_DAYS`), от его
  собственного `goneAt`. Истёкшие вычищаются вместе с настройками (`purgeExpiredGone`) при
  старте и после каждого обновления. В строке — «N d left» (≤ 3 дней — жёлтым).
- `gone` хранится в объекте источника: удалили источник — пропавшие и их настройки
  удаляются вместе с ним.
- **Forget all** (в Nodes) удаляет все `gone` источника; тап по строке пропавшей ноды —
  меню с «Forget now» для неё одной. Оба вычищают её `id` из всех настроек
  (`purgeNodeSettings`).
- Групповые действия (All / None, перетаскивание приоритета) меняют только живые ноды;
  записи пропавших остаются на своих местах (`dragShown` в `80-drag.js`).

## Источник или сервер, выключенный в Nodes

Два переключателя на вкладке Nodes: у источника (`enabled`) и у каждого сервера
(`source.disabledNodes[]` — id выключенных). Оба **никогда не меняют настройки** тех, кто
их использует: включил обратно — источник / сервер снова в тех же профилях и цепочках, с
теми же галочками и приоритетом.

UI выбора серверов везде одинаковый — без чекбоксов и тумблеров: используемый /
выбранный сервер **обведён рамкой**, тап переключает. Галочка целого источника в
редакторе профиля осталась (у неё есть состояние «частично»).

**Режим редактирования** (чтобы в обычном виде нечего было задеть случайно):
- Nodes: кнопка ✎ в шапке → «Done». Обычный вид: без ⋮⋮, тумблеров и рамок; тап по
  серверу — его меню, тап по мс — пинг; выключенные приглушены, у выключенного источника
  метка OFF. Режим правки: ⋮⋮ источников, тумблер источника, рамки у серверов, тап по
  серверу — вкл / выкл; кнопки «пинг всех» и «+» скрыты.
- Список Servers / Profiles: ✎ в шапке. Обычный вид: без ⋮⋮, тап по записи — Manual.
  Режим правки: ⋮⋮ для порядка Auto, тап по записи ничего не закрепляет. Закрытие
  списка выходит из режима.
- Редакторы записи / профиля / цепочки отдельного режима не имеют.

Выключенный сервер остаётся в Nodes (без рамки, приглушён и зачёркнут, в мете «N off»), а
везде остальном его нет: в записях, в редакторах профиля / источника / цепочки, в выборе
ноды, в Auto, в «пинговать все». Групповые действия (All / None, перетаскивание) его
галочку и место не трогают. Для остального приложения источник = `liveNodes(s)`.

Пока выключен:
- его собственная запись в режиме «Простой» скрыта, в пикерах цепочек его нет;
- запись / профиль / сторона цепочки, у которых без выключенного **не осталось ни одной
  ноды**, — «сломанные» (`brokenBy(id)` — что включить: `{sid}` источник или
  `{sid, nid}` сервер; считается как «живых нет, а со всем включённым в Nodes — есть»):
  серые, с красной рамкой, тег OFF, под списком (место в приоритете хранится), Auto их
  пропускает, закреплённая вручную такая запись уступает Auto. Тап — объяснение «то, через
  что она работает, выключено в Nodes» + «Switch on X» для каждого + «Edit …»;
- в Простом режиме запись источника, у которого выключены все отмеченные для неё
  серверы, тоже «сломанная»;
- профиль, у которого есть другие рабочие источники, работает на них без пометки;
- в редакторе профиля выключенный, но используемый источник показан серым
  («off in Nodes»), галочкой его можно только убрать; если профилю без выключенных нечего
  использовать — жёлтое предупреждение с их именами, сохранение заблокировано; в
  редакторе цепочки так же для каждого конца.

Разница с галочками записей: выключение в Nodes — глобальное («этот сервер мне сейчас не
нужен нигде»), галочки (`offNodes`, `profile.nodes`, `inOff/outOff`) — выбор конкретной
записи.

## Удаление источника / сервера

Всегда с подтверждением. В нём — что станет с каждым, кто это использует (`deleteImpact`:
списки обоих режимов пересчитываются «как будто этих серверов нет», `simExclude`):
- текущее подключение идёт через удаляемое → переподключится через следующий рабочий;
- цепочка, у которой удаляемый источник — конец → удаляется вместе с ним (красным);
- запись / профиль / конец цепочки остаётся без серверов → не подключится, пока не
  отметить другой (красным);
- профиль теряет N из M серверов; цепочка: «вход / выход теряет N» (для Priority-выхода —
  «выпадает из порядка приоритета») (жёлтым);
- ничего не затронуто → «Not used in any profile or chain».
После удаления все настройки, ссылающиеся на эти серверы, удаляются насовсем (включая
`gone` удаляемого источника). Ноды подписки не удаляются по одной (вернутся при
обновлении) — для них есть выключение.

## Режимы

`connectMode`: `simple` (по умолчанию) | `profiles`. У каждого режима свои:
список приоритета (`order`), закреплённая запись (`active`), флаг Auto (`auto`).

- **Простой**: записи — сами источники + цепочки из двух источников. У источника
  `offNodes` — выключенные для этой записи ноды.
- **Профили**: записи — профили + цепочки из двух профилей. Профиль: целый источник
  (включая будущие ноды) или отдельные ноды.

Юнит (то, чем является запись или конец цепочки) → список нод: `unitRefs(id)` — живые
ноды включённых источников минус выключенные.

## Auto / Manual

- Auto: подключается первая запись списка с `inAuto`, которая сейчас рабочая
  (`isUsable`: есть живая нода; для цепочки — живые вход и выход).
- Настройки — **Settings → Auto mode** (`autoCfg`, `55-automode.js`); карточка Auto mode
  на главной — просто ссылка (иконка, название, ›) на этот раздел. Вкл / выкл Auto —
  бейдж Auto в списке Servers / Profiles (в настройках тумблера нет):
  | Поле | Значения | Контрол | Смысл |
  |---|---|---|---|
  | `threshold` | 0–1000 мс, **50** | поле ввода | гистерезис: сервер сменяет текущий, только если быстрее на столько; неверный ввод — откат |
  | `checkEvery` | 30 с / **1** / 2 / 5 / 10 мин | выпадающий список | период проверки текущего маршрута (+ standby) |
  | `standby` | 1 / **2** / 3 | чипы | сколько следующих по приоритету записей пинговать вместе с текущей (выключить нельзя) |
  | `failAfter` | 1–4, **2** | степпер ‹ › | таймаутов подряд до ухода с сервера |
  | `pauseScreenOff` | **да** | тумблер | не проверять при выключенном экране, проверить при пробуждении |
  | `subsEvery` | 6 / **12** / 24 ч / выкл | чипы | глобальный период обновления подписок; про свой период подписки — в [?] |
- `source.updateInterval`: `'auto'` (по умолчанию) = `subsEvery`; число часов — свой
  период (0 = не обновлять). В форме подписки пустое поле = auto.
- **Standby («keep warm»)**: внутри юнита sing-box `urltest` и так пингует все свои
  outbound'ы по `interval`; standby нужен для перехода между *записями* списка (и для
  Priority-выхода). Стоимость: один URL-тест ≈ 1–5 КБ; 3 маршрута раз в минуту — порядка
  сотен КБ в сутки. Реальная цена на мобильном — пробуждения радио, поэтому пинги
  standby идут пачкой в том же тике, что и проверка текущего, и ставятся на паузу при
  выключенном экране / режиме энергосбережения. Выигрыш — переключение без поиска: сразу
  на заведомо живой.
- Тап по записи закрепляет её (Manual), повторный тап — назад в Auto.
- Скрытые записи (выключенный источник) в выборе не участвуют.

## Выбор ноды внутри юнита

- Запись (источник в Простом режиме, профиль), `pickMode` (по умолчанию `fastest`):
  - `fastest` — самая быстрая живая (`bestAlive`) из отмеченных; sing-box: `urltest`;
  - `priority` — первая живая по `pickOrder` (ключи `sid::nid`) сверху; sing-box —
    `selector`, как у Priority-выхода ниже.
  Это настройка **записи**, не подписки: у источника она хранится рядом с `offNodes`
  (его запись в Простом режиме), у профиля — в профиле. В Nodes порядка нет.
  UI: чипы Fastest / Priority в настройке записи (в Priority — ⋮⋮ и номера у всех
  серверов, отключённые для записи тоже упорядочены, как у выхода цепочки) и в редакторе
  профиля (блок «Connect through»: в Priority — список выбранных серверов с ⋮⋮). В
  списке у такой записи метка PRIORITY. Невидимые сейчас серверы (выкл. в Nodes,
  пропавшие) при перетаскивании сохраняют место; при удалении / Forget ключи чистятся.
- Вход цепочки: всегда самая быстрая живая из отмеченных (`urltest`).
- Выход цепочки, `exitMode`:
  - `fastest` — самая быстрая живая из отмеченных (`urltest`);
  - `priority` — первая живая по `exitOrder` сверху, при падении — следующая.
    В sing-box нет outbound'а «по порядку»: `urltest` берёт самый быстрый (с `tolerance`),
    `selector` — тот, что выбрали. Поэтому Priority = `selector` из нод выхода, который
    **переключает наш Dart-код** (через Clash API) по результатам пингов: первая живая
    сверху.
  Ноды, которых нет в `exitOrder`, идут после, в порядке источника.
- Цепочка = выходной outbound с `detour` на входной.

## Валидация: хотя бы одна нода

- Профиль, вход и выход цепочки: если не отмечено ни одной живой ноды — жёлтое
  предупреждение, сохранение заблокировано.
- Настройка источника (Простой режим) применяется сразу; если при закрытии не отмечено
  ничего — выбор откатывается к состоянию на момент открытия.

## Пинг

- Один кэш на всё приложение, ключ — сервер (`protocol://address:port`): нода из двух
  подписок пингуется один раз. Значение: мс, `-1` = таймаут, время замера.
- Свежесть 5 минут (`PING_FRESH_MS`): старше — перемерить перед использованием.
- Пинг пары (вход → выход) — выход через `detour` на вход.

## Проверка маршрута цепочки (информационная)

1. Входные ноды: кэш, если все моложе 5 мин, иначе пинг всех.
2. Живые входы от быстрых к медленным; для каждого — пинг всех выходов через него
   (выходы параллельно, входы по очереди). Нода не пингуется сама через себя.
3. Если кэш использован и первые 2 входа не дали ни одной пары — кэш устарел:
   перепинговать входы и начать заново (один раз).
4. Результат: рабочие пары по сумме задержки. Цепочку и Auto не меняет. Пользователь
   может остановить проверку вручную (досрочной остановки по N пар нет — решено).

## Главный экран (ConnectDock)

Показывает, через что идёт трафик сейчас:
- Простой: `Sub|Servers` + имя источника; строка ниже — нода;
- Профили: `Profile` + имя; ниже — источник › нода;
- Цепочка: `Chain` + имя; ниже — нода входа → нода выхода.
Справа — задержка (для цепочки — сумма двух хопов), бейдж AUTO / MANUAL. Иконки слева нет.

## Подсказки [?]

Круглая кнопка «?» у заголовков сложных экранов открывает компактный лист поверх всего
(уровень 3) с 3–6 строками «термин — что делает», простыми словами. Где: Nodes, список
Servers / Profiles, настройка записи, редактор профиля, редактор цепочки, Settings →
Auto mode и Subscriptions, Advanced в форме подписки. Тексты — `HELP` в `58-help.js`.
