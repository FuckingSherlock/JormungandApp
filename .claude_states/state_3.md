- **«VPN не работает» — одно событие** (вместо `core/down` и стоячего `conn/offline`/`online`): причины — ядро
  (не поднялось за 30 с после падения) и нет сети; одна строка, одно уведомление, один переключатель (`connLost`;

  Пока VPN не работает, зависящее от него (подписки, rule set'ы, сайты, DNS…) не уведомляет — только «+N» в строке.
  `conn/lost` («серверы не отвечают») — отдельное событие, как было (проблема подписок/настроек). Закрывающее событие
  заменяет показанное уведомление при любом своём переключателе. Тексты — нормальные слова, не «беда».
  Сделано 2026-10-17; модель — `logs.md` «„VPN не работает“».

## Решения пользователя (в силе, из прошлых стейтов)

- **Не прятать проблемы** (правило в `CLAUDE.md`): никаких «не чаще раза в N», молчаливых дедупов и глушения событий/
  логов; повторы — видимо (счётчик, время, строка в Raw), сокращение видимого — только с согласия пользователя.
- **Нумерация в чате**: один верхний уровень на ответ (1, 2…), подпункты N.1; номера пользователя сохранять.
- **Деплой беты — только по явному «деплой»** (CLAUDE.md, `release-notes/README.md`).
- **Сайты**: проверка только по отвалу приложения; порядок: та же нода → разведчик (рабочая нода той же подписки, другой
  страны) + чекер параллельно (отменяется, если нода открыла) → ноды других подписок. Микросбой — только Raw. Чекер не
  открыл → «мёртв» без уведомления, отвалы 1,5 ч в счётчик, потом проверка одним чекером. Чекер открыл → игнор отвалов
  по лестнице 5/15/30/60 мин. Успешное соединение снимает запись; смена сети — только запись с лестницей.
  `site/blocked` и `site/unreachable` — разные события; «мёртв у всех» — без наших нод в событии.
- **Auto**: мёртвые ноды — лестница 1/2/4/8/15/20 мин (дальше 20), один лёгкий запрос, не сбрасывается (файл ядра),
  переподключение = одна внеочередная проверка, смена сети = сразу; общий заход для всего, что подходит в 2 мин; текущая
  нода не пробуется при живом трафике. Проверяются только ноды основного потока и цели правил.
- **Подключение**: свежая проверка верха списка параллельно, Priority — высшая из ответивших, Fastest — первая + окно
  ~1 с; селектор вместо `urltest`; каталог — в фоне после подключения.
- **Подписки**: пустая / без нод / HTTP-ошибка стороны — неудача стороны без события, если данные получены;
  `sub/diverged` — только разные наборы нод. Интервал обновления — пользовательский.
- **DNS**: гонка протоколов по каждой включённой стороне; UDP — только если все шифрованные молчат; победитель не
  меняется на каждом пинге.
- Окно проверки выходного IP — 20 мин. Запасные чекеры — 4 по умолчанию, не добавлять.
- Журнал позже — таблица хранимых состояний/проблем (`to_think.md`). Raw и репорт читает только агент (`features.md`).
- Per-app DNS — первым в `features.md` (детали обсудить с пользователем до брифа).
