## Сделано в этой сессии
1. **Пинг как в Karing** (9399e18). `core/lib/src/probe.dart`: в конфиге есть loopback SOCKS5-inbound
   `probe-in` со случайным паролем. Имя пользователя = тег outbound'а, route-правило `auth_user` → этот
   outbound (идёт первым). Замер: два HEAD на одном соединении, время второго; если сервер не держит
   соединение, время первого; -1 = нет ответа. Через него работают и пинг каталога (`runtime.dart`
   `measureLatency`), и AutoService (`delay`, в `daemon.dart`). Результат: мосты 64–90 мс вместо 210–290,
   как в Karing у юзера.
   - Найдено: Clash API `/proxies/<tag>/delay` молча меняет любой `http://` URL на gstatic https.
     Старый пинг с http-адресом мерил gstatic, а тесты Auto «на loopback» ходили в интернет.
   - Прямые ноды DE/NL с ПК не отвечают (вероятно, блок), работают мосты.
2. **Локальные сети всегда напрямую** (616d63d). В `routing.dart` правило `ip_is_private` +
   `domain_suffix` [local, localhost, lan, home.arpa] идёт первым, в том числе в Global. `quick.lan`
   убран. В мокапе строка «Local networks direct · Always» без тумблера; в Final order она первая,
   проверка адреса тоже смотрит её первой. Доки: `rules.md` §2, §7.
3. **Шаг 2: запасные** (77ece09). `failAfter` 1–5 (ядро clamp 1–5). Тумблер `keepWarm` убран:
   `standby` 0–20 теперь слайдер «Spare servers», 0 = выкл; старый план с `keepWarm:false` читается как 0.
   Новый `warmEvery` («Ping the spares every», 10 с – 60 мин, по умолчанию 60 с): запасные меряются на
   проверке текущего, когда подошёл срок (до 1 с раньше считается), поэтому не чаще `checkEvery`.
   В плане (`94-live-auto.js` `planRoutes`) ниже якоря минимум 2 записи, чтобы без запасных failover
   было куда идти. Это временная затычка до шага 3 (все записи в конфиг).

## Решено юзером, не сделано (подробно в `docs/`)
- **Отказ ноды, ошибки запросов, чекеры**: `docs/connect-model.md`, раздел «Отказ ноды: ошибки
  запросов и чекеры (решено, не сделано)», схема из 5 шагов. Кратко: падение → сначала пинг самой
  ноды; чекеры = список гарантированно доступных сервисов плюс свой адрес юзера. Нода живая, если прошёл
  хотя бы один чекер. Одиночный упавший запрос при живой ноде → уведомление «адрес недоступен с ноды»
  + заготовка правила. ОС офлайн → «подключено без интернета», ничего не помечать мёртвым. Отдельное
  состояние «сломана», перепроверяется пингом по чекерам.
- **Kill switch**: когда всё упало, блокируем, но правила с явной целью Direct пропускаем. Пока kill switch
  включён, висит алерт. `docs/rules.md` §7. При офлайне ОС не забыть про kill switch: утечка возможна в
  окне до 10 с.
- **Настройка «пинг на тот же / соседний сервер после ноды»** юзер предлагал, чтобы проверка работала
  при минимальной добавочной задержке. Пока только идея; сейчас свой URL проверки задаётся в
