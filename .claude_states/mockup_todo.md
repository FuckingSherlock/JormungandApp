# Отложенные правки мокапа

Мокап (`design/src`) заморожен с 2026-10-06 ради экономии токенов: изменения логики и UI идут в core + Flutter,
а сюда пишется, что перенести в мокап, когда вернёмся к ПК-версии.

- `site/unreachable` с `data.check.state == 'down'` (недоступен и для чекера): карточка не упоминает наши маршруты (нет строк entry/server, списка tried, заметок «нет другого маршрута» / retries, поля скрыты и в раскрытой карточке); в `data`/`trail` они остаются. Мокап: карточка site-unreachable в `design/src/js`; docs/failures.md (Проверки сайтов), connect-model.md (внешний чекер).
- Серии `conn/failing` сверх `FailureBook.maxEvents` (6 за 10 мин) больше не молчат: прибавляются к новейшему `conn/failing` (`data.repeat`) со строкой в сыром логе, нового события нет. Docs: failures.md.
- Connect (этап 2b): подключение больше не ждёт пинга каталога и не стартует на первом сервере списка — ядро проверяет верх главной группы (вход цепочки) на отдельном sing-box и стартует на самом быстром из первых ответивших (Fastest) / самом высоком из ответивших (Priority); нет сети — первый по рангу. В мокапе: демо-старт группы Fastest/Priority на выбранном сервере (`12-backend.js` / `95-live.js` connect), `conn/connected` с `pick` и Raw-строка `connect: …`. Выходы цепочек и цели правил при подключении пока не проверяются (этап 2c). Docs: core.md «Подключение: проверка перед стартом», connect-model.md «Внутри маршрута», «Выбор ноды внутри юнита».

- FakeIP убран из core/Flutter до переработки: в мокапе убрать строку FakeIP и «Real answers for» в Settings → DNS, суффиксы « · FakeIP», пункт справки FakeIP, `dnsCfg.fakeip` / `fakeipExclude`; потом перегенерировать golden (тест пока вырезает эти ключи, `_dropFakeip`).
- `20-profiles.js` `chainExitOrder`: узлы, которым цепочка не задала порядок, идут в порядке `pickOrder`
  юнита выхода (подписки/профиля): `orderRefs(orderRefs(unitRefs(...), unitOwner(c.outId)?.pickOrder), c.exitOrder)`.
  Как в core `catalog.dart` `chainExitOrder`.
- `70-profile-forms.js` ~307: убрать `goneBlockHtml` из редактора цепочки (`cc:${side}:${id}`) —
  пропавшие серверы в цепочке не показываются (docs/connect-model.md «Пропавшие ноды»).

- Logs: диагностика и отчёты (Flutter + core, 2026-10-10; док — `docs/logs.md`, когда K2 закоммитит). Что перенести в `35-logs.html` / `46-logs.js` / `47-events.js` / `67-logs.css`:

  - Фильтры Events покрывают каждый тип события (в каталоге `eventCats` ядра ничего не остаётся без категории: семейство `update*`, `conn/failing`, `core/tunTcpDead` / `tunTcpBack`, unstable подписки и т.д.); поиск находит по тексту события и по данным.
