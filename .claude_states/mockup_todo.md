# Отложенные правки мокапа

Мокап (`design/src`) заморожен с 2026-10-06 ради экономии токенов: изменения логики и UI идут в core + Flutter,
а сюда пишется, что перенести в мокап, когда вернёмся к ПК-версии.

- `20-profiles.js` `chainExitOrder`: узлы, которым цепочка не задала порядок, идут в порядке `pickOrder`
  юнита выхода (подписки/профиля): `orderRefs(orderRefs(unitRefs(...), unitOwner(c.outId)?.pickOrder), c.exitOrder)`.
  Как в core `catalog.dart` `chainExitOrder`.
- `70-profile-forms.js` ~307: убрать `goneBlockHtml` из редактора цепочки (`cc:${side}:${id}`) —
  пропавшие серверы в цепочке не показываются (docs/connect-model.md «Пропавшие ноды»).
- Route: переключатель Simple / Profiles только показывает режим (точка — режим в работе); полоса
  «Сейчас маршрут идёт через X» + «Использовать этот режим» — единственное, что меняет режим; пустой
  режим — «Профилей пока нет» + «Создать профиль» / «Добавить подписку или сервер» (закрывает лист,
  Nodes «+» на той вкладке). Док / кнопка питания: текущий режим пуст, другой нет → Route на другом
  режиме (`dockTap`, `toggleMain`); вторую строку дока для этого случая можно переформулировать.
- Golden: после переноса — перегенерировать `core/test/golden/catalog.json` и очистить `_mockupBehind`
  в `core/test/catalog_golden_test.dart` (пока там пропущены сценарии, где core ушёл вперёд мокапа).
- Лист Notifications: строка-предупреждение «Уведомления заблокированы» + «Открыть настройки» (на
  телефоне, когда POST_NOTIFICATIONS запрещено), как `NotifPermissionHint` во Flutter.
- Лист Notifications: под Status на телефоне вторая подсказка «Если выключить, уведомление скрывается.
  VPN продолжает работать; значок ключа — от Android…» (Flutter: `settings_look.dart`, `NotifSheet`);
  мастер и Status выключены = постоянное уведомление VPN скрыто совсем.
- `42-apps.js`: в комментарии-шапке — приложение с правилом, которого нет на устройстве, остаётся
  видимым в User и Configured.
- Фильтр подписки (`updater.dart`): отфильтрованные серверы не попадают в `gone`. В мокапе логики
  обновления нет (mock backend) — переносить нечего, только если мок имитирует `gone` по фильтру.
- Settings → Data (блок App updates): строка «Auto-download» (`genCfg.updAutoDownload`: `off` / `wifi` по умолчанию / `always`) между Auto-check и Channel; серая, когда Auto-check выкл. Выбор: Off / Wi-Fi only / Always (в браузерном макете платных сетей нет — можно показывать Off / Always). Подпись «Downloads what Auto-check finds; installing stays yours». Flutter: `settings_data.dart` (`_UpdatesBlock`); в бэкап через genCfg; нужна и мок-логика (`mockUpdate`) — после найденного плановой проверкой сразу `downloading` → `ready`. Док: `docs/updates.md` §6, §11.

- Route (Flutter app): раскрытая строка цепочки показывает стороны Entry / Exit с серверами (как карточка в Nodes), раскрытие по тапу на карточке, без шеврона. В мокапе у цепочек в Route разворота нет — добавить (`js/20-profiles.js`), см. docs/connect-model.md «Каталог (Nodes) и Route».
- Выход цепочки живёт по **паре** (вход в работе → выход), не по прямому пингу (docs/connect-model.md «Пинг», «Auto / Manual»). Мокап: кэш пар рядом с `pingCache` (`15-ping.js`, ключ `pingKey(вход)+'>'+pingKey(выход)`, поля ms/at/fails, в снимок `pairs`); `pingNodes` не пингует выходы цепочки напрямую — `pingEntry` цепочки / «ping all» выходов в редакторе / пинг при запуске: входы напрямую, выходы парами (`backend.pingPair`) через `chainEntryNode`, результат в кэш пар; `testChainRoute` (`70-profile-forms.js`) пишет каждую пару туда же. `20-profiles.js`: `chainExitNode` (выбор/порядок выхода по паре; прямой ответ — подсказка, только живой, пока пары нет), `mayWork` / `knownDead` цепочки (выход «мёртв» только по паре через вход в работе, иначе по свежему живому ответу пары через другой вход), `isUsable`, `effectiveConnectId`, `planRoute` (порядок выходов Fastest по мс пары); задержка цепочки в доке/карточке = мс пары (сумма хопов — пока пары нет); строки выходов в карточке цепочки / Route показывают мс пары. Core: `Catalog.pairs` (`PairBook`), `chainPair` / `chainExitEntry` / `chainExitNode` / `chainLatency` / `byChainPing`. Golden: сценарии `src1-dead`, `op-auto-off` расходятся (в `_mockupBehind`), после переноса — перегенерировать golden и снять.
- Route (Flutter app): ⟳ «Update» стоит на карточке строки постоянно рядом с ⚡ (подписка; профиль — все его подписки; цепочки нет), не только в развороте. Кнопки действий (⚡ ⟳ ✎ ⋮) в Route и на карточках Nodes крупнее: 48 dp цель, иконка 22 dp. В развороте Route (подписка / группа / профиль, у цепочки — списки выходов и входов) мёртвые серверы (`knownDead`; выходы цепочки — `chainExitKnownDead`) собираются в блок «Unavailable · N» в стиле `goneBlockHtml`: первые 2, «Show all N» / «Show less». Не в Nodes. Док: docs/connect-model.md «Каталог (Nodes) и Route». Мокап: `20-profiles.js` (кнопка и блок), CSS кнопок.
- Dock-ping цепочки (тап по задержке в доке, `pingDockTop`): первая пачка «по 3 с каждого конца» — выходы пачки меряются парами через вход, не напрямую (во Flutter сделано: `Catalog.dockPingBatches` / `DockPingRun` в `core/lib/src/catalog/dock_ping.dart`; макет всё ещё пингует выходы напрямую).
- Logs (Flutter beta.20+): Raw — чип «Connections» (выкл. по умолчанию, `logCfg.showConns`) скрывает удачные соединения sing-box; Events `site/*` — кнопки «Copy site» и «Create rule» всегда при наличии хоста; Open на цепочку Simple открывает вкладку Simple (`modeOf`). Перенести в мокап (35-logs / 46-logs.js / 47-events.js) + строки «Copy site», «Site copied». Док: docs/connect-model.md «Вкладка Logs».
- Logs: «Игнорируемые сайты» (Flutter): меню ⋮ в шапке Logs → лист со списком (добавить с проверкой хоста / убрать / «Clear all»); «Ignore site» на событиях `site/*` с хостом, на тосте и на системном уведомлении (вместе с «Create rule»; тост — обе кнопки под текстом, не `SnackBarAction`) → тост «{host} ignored · Undo»; в Raw — чип «N from ignored sites» (`logCfg.showIgnored`, выкл. по умолчанию), скрытые строки — warn/error, где упомянут хост или поддомен. Хранится в `notifCfg.ignoredSites` (бэкап), ядру уходит в `updateSettings {ignoredSites}`. Мокап (46-logs.js / 47-events.js / 35-logs.html / 04-i18n-ru.js) перенести; у jormd списка нет — фильтр событий `site/*` там делать на стороне UI. Док: docs/connect-model.md «Игнорируемые сайты».
- Logs / Notifications: «Фоновые ошибки» (Flutter): site/* события, найденные при выключенном экране, ядро помечает `bg: true`; в Events строка с луной и «background», в листе фильтра строка «Background» (показать/скрыть); Settings → Notifications → «Errors while screen is off» (`notifCfg.bgErrors`, выкл. по умолчанию, только Android) решает, уведомляют ли они. Мокап (47-events.js, 04-i18n-ru.js, настройки уведомлений) перенести — в мокапе экрана нет, достаточно строки в фильтре и переключателя. Док: docs/connect-model.md «Фоновые ошибки».
- Источник запроса — приложение (Flutter, Android): `site/*` с `data.app` (пакет) — строка «App» со значком (плитка-буква в моке) и именем (`Android System` для `android`, id пакета если неизвестен), тап → диалог приложения (`openAppAct`); то же в Live connections (значок + имя в строке соединения и в деталях, тап закрывает лист) и после Raw-строки `found package name: …`. Док: docs/connect-model.md «Строки причины», docs/core.md.
- Logs / Auto (Flutter): внешний чекер check-host.net — `site/unreachable` с `data.check` (`pending` / `opens` / `down` / `failed` / `off`): строка вердикта «Opens elsewhere, not through your routes» / «Down everywhere (check-host)» / «Asking check-host…» в карточке события, в раскрытой строке «Checker» с узлами (страна, город, OK код · мс / ошибка); кнопка «Check with checker» (при спросе «Checking…», тусклая) на `site/*`; Settings → Auto mode → тумблер «Check with an external checker» (`autoCfg.siteCheck`, по умолчанию вкл., в снимок и план пишется только `false`). - Редактор цепочки: «Disabled in subscription · N» (Flutter): у конца-источника серверы, выключенные в собственном редакторе подписки (offNodes), сворачиваются в блок под списком (свёрнут по умолчанию, тап по заголовку раскрывает; подпись «can be switched on for this chain only»); тап по строке включает сервер только для этой цепочки (chain.inOn / outOn, ключи `sid::nid`) — он переезжает в основной список конца (рамка, участвует в Auto / плане / паре / приоритете выхода), тап по нему снова возвращает в блок; в самой подписке, Simple / профилях и Nodes он остаётся выключенным. Строки «Disabled in subscription · {0}» / «Отключены в подписке · {0}», «can be switched on for this chain only» / «можно включить только для этой цепочки». Мокап: 70-profile-forms.js (редактор цепочки), 20-profiles.js (chainEntryRefs / chainExitOrder = юнит + forced),  4-i18n-ru.js, снимок/бэкап — поля inOn / outOn пишутся, только если не пусты. Core: Catalog.chainOffRefs / chainForcedRefs / chainSideRefs, chainForceNode. Док: docs/connect-model.md «Сервер, выключенный в подписке, но включённый для цепочки».

- Home → карточка Speed Test (Flutter): тап меряет текущее подключение (network quality test через `proxy` работающего sing-box); не подключено — карточка приглушена, тост «Connect first»; идёт — кольцо вокруг иконки + «Measuring latency…» / «Speed test: ↓ N · ↑ M Mbps», второй тап отменяет; результат двумя строками («↓ 87 · ↑ 22 Mbps» / «34 ms · 12:41»), «Test failed» при сбое; Logs → Events новая категория `speed` (`done` / `failed`, значок speed, цвет purple). Мок: `50-home.js` (карточка), `12-backend.js` (мок-замер текущего), события, `04-i18n-ru.js` (строки «Connect first», «Speed test finished», «Speed test failed», «Speed test: ↓ {0} · ↑ {1} Mbps», «Latency {0} ms»). Док: docs/connect-model.md «Speed Test текущего подключения».
