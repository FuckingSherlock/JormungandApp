- Сервер мёртв на одной стороне из своих — остаётся в списке, мёртвый чип приглушённо-красный; в секцию — только мёртв на всех.
- **В работе (D3):** агент A (coder-deep) — ядро+docs: Local закреплён первым/последним по `directPolicy` (`routing.dart`
  `_side`), `docs/rules.md` §6; агент B (coder-deep) — приложение `app/lib/widgets/settings_dns.dart` (+ l10n,
  `mockup_todo.md`). Без коммита; лид проверяет и коммитит.
- У провайдера всегда ≥1 сторона и ≥1 транспорт: нажатие на единственный горящий чип стороны молча
  переключает на другую сторону; последний транспорт не снимается; выключать сервер — галочкой. Предупреждение о последнем сервере стороны — честное (1.1): прямая → «DNS прямого трафика пойдёт через
  VPN-серверы»; VPN → «пойдёт мимо туннеля, провайдер увидит сайты»; обе пусты → DNS системы.
- Пропущено в D3, делается до беты: в форме сервера чипы транспортов DoH/DoT/DoQ/UDP (`use`; видны только виды, для
  которых есть адреса; последний не снимается); свой сервер — список адресов разных видов (+ адрес, вид по адресу), как у
  встроенных (решение 1.1). Этап A: модель + форма; этап B: виджет-тесты.
- Решено: адреса (transports) встроенных НЕ хранятся — при загрузке всегда из кода (`defaultDnsServers`); в настройках
  только on / sides / use / name / порядок. Обновление адресов доходит до всех без миграций. Этап C (ядро), после A/B.
- `directPolicy` переносит Local наверх (Local first) / вниз (по общему приоритету) и закрепляет там, перетащить нельзя;
  Local выключен → настройка серая.
