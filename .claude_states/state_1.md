## Решено по п. 0 (2026-10-12, сессия state_1 продолжается)

- Путей служебного трафика N, не 2: напрямую, основной маршрут, любой другой рабочий маршрут/нода. Гонка самим
  запросом (проба только для POST), учитывать, есть ли вообще рабочий путь, — не сыпать ошибками со следствиями.
- Победитель запоминается по хосту в текущей сети; гонка заново после сбоя / смены сети / переподключения.
- Повторы: свой перезапуск → повтор после «устоялось»; сетевой сбой → 1→2→5→15 мин, сброс сменой сети/переподключением;
  нет сети → ждать. Ошибку показывать только когда подтверждено: сбой постоянный, нет очевидной внешней причины
  (нет сети), нет простого решения (смена метода/цели).
- **Начать с общего механизма проверок перед объявлением сбоя** — на него уже ссылаются п. 1, 2, 4 и «ложные сигналы».
- Rule set'ы: обновление во время работы, честный текст. Настройки (свои адреса, период, автообновление) — позже в
  переработке меню правил (`to_think.md`), сейчас только почва под свои rule set'ы.
- Обновления приложения: автоматика; переключатель «direct / основной маршрут» vs «direct / любой маршрут».
- GeoIP/GeoSite = те же rule set'ы, отдельного нет.
- Механизм проверок (дизайн принят): контекст сети/ядра → подозрение → лестница проверок → подтверждённая первопричина,
  следствия привязаны к ней. Captive portal — делать. Краткий восстановившийся сбой — в журнал, но конкретно что.
  Подробности события = протокол проверок механизма (что проверено, что подтвердило причину). Отправка отчёта событий
  не пишет — так и остаётся. Переключатель пути обновлений — в `to_think.md`, пока через основной маршрут.
- Подписки: 3 варианта «Download via» — Auto (сразу обоими путями, по умолчанию; бывшие Proxy first / Direct first
  мигрируют в него), строгие Proxy и Direct. Оба ответили, данные расходятся — запись в журнал. (HWID VPN не скрывает,
  IP провайдер видит при добавлении — доводы против параллельности отпали.)

  обоих в пределах grace берётся туннель. Исключение — скачивание обновления приложения: если direct получил тестовые
