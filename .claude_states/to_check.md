# Проверить пользователю

Сюда — частные вопросы, на которые отвечает только ручная проверка пользователя (телефон, TUN, реальная сеть):
«работает ли X в такой-то ситуации», от ответа зависит, нужен ли код. Не общий прогон функционала версии.
Проверено — пункт удаляется; если нашёлся косяк — уходит в `bugs.md`, если нужен код — в свой план.

## Телефон

- **Перепроверка рядов карточки сайта** (43e68d5, 2026-10-24; в бету ещё не входила): ряды не пропадают, нажатый
  гаснет → пульсирует жёлтым → цвет нового итога. Не мелькает ли на миг старый цвет перед новым (ревьюер: если новый
  итог приходит из ядра позже конца проверки). Если мелькает — ждать новые данные до снятия busy (`event_card.dart`
  `_CheckRowViewState.didUpdateWidget`). Заодно: шевроны всех рядов у правого края; тап по карточке не раскрывает.
- **Правила приложения** (2e42751, 2026-10-21):
  - Т-Банк: в листе приложения правило `cdn.t-bank-app.ru` → Direct при маршруте приложения Default + Fallback —
    сайт идёт напрямую (Raw / Connections), остальной трафик приложения — по маршруту приложения.
  - Перенос при обновлении: старые правила с условием «Приложение» оказались в листах своих приложений, в журнале одна
    строка `rulesMoved` со списком; не перенесены «кроме», составные и правила только из приложения. В форме своего
    правила условия «Приложение» нет.
  - Событие `site/*` с приложением: строка App открывает лист приложения, строка Rule — существующее правило адреса
    (не дубль); без правила — «New rule for <host>», в Fallback предложена открывшая нода, сохраняется только по Save.
  - `site/unreachable`: Create rule нет, в свёрнутой строке — Copy site.
  - Лист приложения: список правил с тумблерами и перетаскиванием, при > 4 — «N more»; то же в общем списке правил.
  - Приложение с маршрутом Direct и включёнными правилами: правила работают (приложение не выкинуто из VPN через
    `exclude_package`); без правил — выкинуто, как раньше.

- **Captive portal при поднятом VPN** (из `events_plan.md` т2 п. 1). Подключиться к сети с порталом входа (гостевой
  Wi-Fi, кафе) с включённым VPN и посмотреть, приходит ли системное уведомление Android «Войдите в сеть». Приходит —
  своего события не делаем (решение 2026-10-17; корень Sentinel `net.captive` и свёртка следствий остаются). Не
  приходит — вернуть в `events_plan.md`: тогда нужно своё уведомление.
- Тихая установка обновления на Android 12+ (S47; из `features.md`).
- Android 8–9: procfs-владелец соединения; на API < 31 монитор сети не берёт VPN как «сеть по умолчанию» (S58).
- Kotlin: `registerMyInterface` — пустышка (`LibboxPlatform.kt.tmpl:195`); не лежит ли секрет API sing-box открыто в
  `filesDir/libbox/configuration.json` (S63) — это проверка по файлу на телефоне, можно через adb.

## Быстрый старт (2026-10-21)
- Отключить и подключить снова в той же сети: подключение без ~5 с ожидания (сразу на прежнем сервере); в событии `conn/connected` нет строки переключения, если сервер жив.
- Сменить сеть (Wi‑Fi ↔ мобильная) между отключением и подключением: обычная проверка перед стартом (как раньше).
- Отключить, сделать прежний сервер недоступным (или выше в Priority ожил сервер), подключить: событие подключения само дополняется строкой «… switched to …» без отдельного reconnect.
