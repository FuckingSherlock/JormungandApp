Схемы: net/switched и rules/fallback

Тексты UI на английском (как в приложении), пояснения — на русском. Тот же вид карточки, что в схемах DNS / сайта: иконка в строке времени, блок данных во всю ширину, Details ▾ первой, тап по карточке ничего не открывает.

1. net/switched — смена сети

Что есть сейчас: info-событие, data {from, to, downMs?}, каждое из {type, provider?, operator?, metered?}. Текст — «Wi‑Fi (Ростелеком) → Mobile (МТС)» (_netSide, event_text.dart:1209), с провалом «· no network N s». Само событие ничего не говорит о туннеле: следствия (переподключение, dns/switched, auto/switched, auto/fastest) — отдельные события, у которых в окне смены cause = это событие (docs/logs.md:404). Поэтому «что стало с туннелем» берём не из data, а из свёртки: дочерние события под корнем.

  • Две цепочки-карточки «A › B»: имена сетей короткие (мобильная — «Mobile · оператор»; Wi‑Fi — просто «Wi‑Fi»: имя сети (SSID) ядро не берёт, на Android нужно разрешение геолокации, logs.md:564), провайдер/«metered» — подпись. Красный→зелёный здесь не про «плохо→хорошо», а про «было→стало»; как в DNS.
  • Блок Tunnel — только если что-то было в окне смены; пусто = блока нет. Строки берутся из дочерних событий (conn/reconnected, dns/switched, auto/*) — «нужно новое поле: effects[] в data или свёртка по cause на стороне приложения».
  • Gap — downMs; нет поля — нет строки.
  • Cause — только когда есть провал (downMs) или тип сети изменился; иначе строки нет. «нужно новое поле: why: lost / roamed / handover» — сейчас различить можно только по downMs.

2. rules/fallback / rules/targetBack

Цель правил (подписка / нода / основной поток) перестала отвечать — их трафик ушёл на «If unavailable». Одно событие на пару «цель + запасной выход». data {rule?, app?, more?, target, to: 'block'|'direct'|'main'|<id запасной цели>}; targetBack {rule?, app?, more?, target} закрывает его. Контекст: rules/targetLost — цель потеряна (удалена / выключена / нет серверов), тут же цель просто не отвечает; корень — отказ сервера в Auto (auto/switched, docs/logs.md:412). Текст сейчас: «<X> не отвечает — трафик правил переведён на <запасной выход>».

  • Не видно: какая именно нода цели молчит и куда ушёл трафик (одно слово «Direct» в подзаголовке).
  • У пары нет длительности; «Check now» непонятно на что (цель = подписка из многих нод).
  • Без цепочек «нода › нода»: имена нод длинные. Target = плохая строка (красный градиент), Now = хорошая (зелёный), оба с «подписка · протокол» и └ нодой, › справа — переход к узлу в Nodes.
  • Rule: имя первого правила, «and N more» — из more (тап — к правилу; остальные видны внутри формы правила). При app вместо правила — иконка приложения.
  • Закрывающее targetBack — зелёная OK-карточка, пара с fallback (одно событие, длительность в заголовке). «нужно новое поле: forMs в targetBack» (или считать по времени пары).
  • Cause берётся от корня: auto/switched / отказ сервера; нет корня — «not established».
НОВОЕ — запасной выход не нода: Direct / Block / Main flow; цель — основной поток

Открытые вопросы

  • net/switched: блок Tunnel (A) или одна строка итога (B)? Откуда брать следствия — effects[] в data или свёртка по cause в приложении?
  • net/switched: нужна ли строка Cause («Wi‑Fi lost» / «roamed») и поле why?
  • rules/fallback: показывать конкретную ноду подписки, которая не отвечает (target — id/причина, нода нужна как новое поле node)? Длительность в targetBack (forMs)?
