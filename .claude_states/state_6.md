# State 6 (черновик, дополняется до конца сессии)

Отправная точка — `state_5.md`; ограничения — `state_3.md` «Ограничения».

## На потом (юзер: «в долгий ящик» / «просто в план»)
- Проверка сервиса через узлы: в пикере цели правила второй индикатор у каждого узла —
  открывается ли хост из правила через этот узел (переиспользовать probeReach + пул). Категории
  ответа: 2xx/3xx ок, 403/451 отказ (геоблок / бан IP), сброс TLS (DPI), таймаут. 403 считать
  блоком, только если через другие узлы / напрямую 200 (иначе это защита сайта от ботов).
  Запуск по ⚡ в шапке пикера, не при каждом открытии.
- Аудит «проверок через сервер, который юзер явно не выбирал» + настройка (по умолчанию вкл,
  можно выключить). Причина: сервисы смотрят не только на IP — запросы к одному сервису с разных
  адресов при одинаковых прочих параметрах могут снизить траст. Различать: запросы на
  нейтральный test URL (безвредны) и запросы к реальным адресам юзера (site/blocked: повтор сайта
  через другой маршрут в auto.dart `_sites`; будущая проверка сервиса). Выключено → такие
  повторы не делаются, событие «не открывается» без варианта «через B открывается».
- Диалог удаления цели (`targetImpact`) не называет запасную цель правила (fallbackTarget).
- Fallback на Route = Direct — отложен (непонятно, как надёжно определять недоступность Direct).
