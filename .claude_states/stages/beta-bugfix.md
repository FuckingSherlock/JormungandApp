# Этап: фиксы багов беты (после beta.13 — переработка событий)

Дочерняя сессия. Родитель — сессия беты (план, переводы, деплой, приём отчётов). Правила работы, ветки, коммитов,
агентов — `CLAUDE.md`. Пользователю отвечаешь сам, вопросы задаёшь ему напрямую. Родителю пишешь только когда
пользователь скажет: «спроси у родителя» (один короткий вопрос) или разрешит отчёт по этапу (коммиты, что проверено —
команды + результат, что осталось).

Начни с `.claude_states/state_3.md` (что сейчас в коде) и `release-notes/beta.txt` (что вошло в бету). Баги
пользователь опишет сам — жди его описания, сам список не составляй.

## Как работать

- Каждый баг, описанный пользователем, — сначала в `.claude_states/bugs.md` (что видно, на какой версии, шаги),
  потом диагностика. Логи и репорты с телефона — `log-analyzer`, сам не читаешь.
- Диагностика — твоя (не в workflow). Баг с известной областью поиска → `coder-deep` «проверь гипотезу, потом почини»
  (может написать свой тест). Мелкая правка в известном месте (≤ ~2 файла, ~30 строк) — сам.
- Если починка меняет поведение — сначала док (`docs/logs.md`, `docs/failures.md`, …), потом ядро, потом приложение;
  заметка в `mockup_todo.md` в том же коммите. Если поведение под вопросом — согласуй с пользователем до брифа.
- Найденное попутно (не то, что описал пользователь) — в `found_bugs.md`, не в `bugs.md` и не в работу без его
  подтверждения.
- Проверка, которую может сделать только пользователь (телефон, TUN, реальная сеть), — в `to_check.md`.
- Новые строки только на английском. Деплой беты не делаешь — это родитель, по «деплой» пользователя.
- Перед коммитом полные наборы: ядро `cd core; dart analyze; dart test`, приложение
  `cd app; flutter analyze --no-fatal-infos; flutter test` (через `test-runner`).
