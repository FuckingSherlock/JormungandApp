Схемы 2: conn/reconnected, «X / X» у site/*, dns/failed и failedOnNode

Тексты UI на английском, пояснения — на русском. Стиль и карточки ev2 — как в согласованном dns_site_schemes.html. Жёлтым «нужно новое поле» помечено то, чего ядро сейчас не пишет.

1. conn/reconnected — что вызвало переподключение и что изменилось

Что есть в ядре (service.dart:4195-4207): reason = settings (своё переподключение живого соединения по действию пользователя) / lists (докачаны списки) / reresolve (пересчёт адресов) / user (ручное «отключить → подключить» за ≤ 7 с; ещё downMs), tookMs, cause (сетевая причина, если была). Для settings в changed попадают только mode (tun/proxy) и route (global/rules). Всё остальное (правила, DNS, нода, системный прокси) в changed не попадает: нода и sysProxy приложение достаёт из user/pin / user/sysProxy той же операции (_reconnectSettings), а правка правил — нет ни там, ни там. Отсюда «Reconnected · by you / settings».

  • Заголовок «Reconnected by <who> (<what>)»: who — you (own: свои настройки, ручное отключить → подключить) или core (lists — докачаны списки правил, reresolve — у сервера сменился адрес). Других источников у события нет. Ряда By и подписи Changed нет.
  • what — что поменялось: rules / mode / server / DNS / system proxy, через запятую. Нечего назвать — без скобок.
  • Правила — одной строкой «2 changed, 1 added», без кнопки: открывать нечего, имена — в Details.
  • Mode и server — стрелкой ›, нейтральной (это не сбой, не красим). Details здесь не нужен, как и у «отключить → подключить».
  • Server address (reresolve) — не про сеть: сервер перестал отвечать, ядро перепробовало закэшированные адреса его домена или узнало новые и перезапустило sing-box с новым IP. Кнопка «Network event» в прошлом варианте была ошибкой.
  • Смена сети: переподключение с причиной-сетью (cause = сетевое событие) — строкой внутри карточки net/switched, вместе с прочими последствиями (DNS, Auto). Само событие остаётся в журнале, в ленте — свёрнуто в родителя (видимо, не скрыто).
  • Нужно новое поле: changed.rules {added, removed, edited}, changed.node, changed.dns; для reresolve — host, from, to (сейчас только в строке лога).

Открытые вопросы пользователю

  • reconnected / правила: ядро сравнивает старый и новый план и пишет changed.rules сам, или приложение пишет tap user/rules (как pin)?
  • reconnected: показывать «was …» малым под изменённой строкой?
  • site X/X: ядро должно не писать via == server; проверить в core отдельной задачей.
  • site/unreachable и n518c…: поздний unreachable не пробовал цель правила — нужен отдельный разбор ядра (лестница tried против viaTarget).
  • dns/failed*: согласны на новые карточки и на поле с именем DNS-сервера в data?
