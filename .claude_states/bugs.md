## DNS (beta.12; скрины пользователя 2026-10-15, разведка там же)

Лист `app/lib/widgets/settings_dns.dart` (`_DnsSheetState` ~76–330, форма `DnsForm` ~769–1222); ядро —
`core/lib/src/dns_failover.dart` (`pingProvider` ~760, `providersJson`/`_groupJson` ~1230), `service.dart`
`pingDnsSides` ~3255; приложение — `core_host.dart` `pingDnsSides` ~652 (без ядра), `live_core_host.dart` ~1198;
`core/lib/src/dns_probe.dart` `dnsLatency`. Документ — `docs/rules.md` §6; заметка в `mockup_todo.md`.

1. **Чипы Direct/VPN скачут по строкам.** Ширина колонки стороны = max(чип, пинг, строка протокола); у строки со
   спиннером или без протокола колонка уже → чипы сдвинуты. Решение (пользователь): протокол — в строке пинга
   (`84ms DoH`), пробел между числом и `ms` убрать; колонка стороны фиксированной ширины (по самому длинному
   варианту при 120 % / 320 px), спиннер и «—» в той же ширине. `84ms` без пробела — **везде** (решено 2026-10-15):
   общий формат `LatencyView` (`latency_text.dart:54`) и все прочие места, где мс пишутся с пробелом (грепнуть
   `' ms'` / `} ms` в `app/lib`, ARB/i18n-строки, тесты-ожидания).
2. **У AdGuard в форме нет строк протоколов**, хотя VPN-пинг в списке есть. Причина (по коду): строки формы
   (`_raceRows`) строятся только из ответа `pingDnsSides`, а ядро отвечает, лишь когда **все** транспорты провайдера
   проверены (`pingProvider` ждёт `Future.wait(nodes.map(_test))`, каждый `_ask` перебирает имена проверки по очереди
   с таймаутом). У AdGuard 5 транспортов, DoQ/UDP не отвечают → ответ идёт десятки секунд, всё это время строк нет
   вообще (не спиннеры). У Cloudflare всё отвечает быстро — строки есть. Состояние `testing` в `providersJson`
   задумано, но наружу не доходит: ответ приходит уже без него. Проверить гипотезу на dev jormd (подключение без TUN,
   `POST /api/dns/ping {provider: adguard}`, время ответа). Решение: ping ядра не ждёт проверок — запускает
   (`unawaited`) и сразу отдаёт текущий `providers` с `testing`; форма опрашивает, как уже умеет (`_raceLoop`).
3. **(!) у кнопки Ping, хотя всё отвечает.** Кнопка формы (`_pingDraft`) — отдельный пинг **одного** адреса
   (первый включённого вида) **из процесса приложения** (`dnsLatency`), мимо ядра и сторон. Проверено на ПК:
   `dnsLatency('https://1.1.1.1/dns-query')` = -1, при этом `tls://1.1.1.1` = 90, `https://8.8.8.8/...` = 299;
   у AdGuard из процесса: DoH 303, DoT -1, UDP -1. То есть (!) — результат другого пути, а не провайдера. Решение:
   у сохранённого провайдера Ping = гонка ядра (строки протоколов), итог рядом с кнопкой — из неё (лучший ответ
   / «нет ответа», только когда не ответил ни один транспорт ни на одной стороне) или убрать; отдельный
   `dnsLatency` — только для несохранённого черновика, и тогда по каждому адресу, а не по первому. Отдельно
   выяснить, почему Dart `HttpClient` не получает DoH от 1.1.1.1 (curl-проверка не сделана) — баг `dnsLatency` или
   сеть.
4. **Пинги протоколов видны только после запуска проверки.** Строки формы должны быть всегда: из конфига провайдера
   (включённые стороны × включённые виды), значение — последнее известное: `status.dns.providers` (`dnsHealth`,
   пока подключено), иначе последний пинг, иначе «—»; спиннер — пока `testing`. Без ядра (не подключено) прямая
   сторона меряется в процессе **по каждому транспорту** (сейчас `CoreHost.pingDnsSides` отдаёт один лучший и без
   `races`), VPN-сторона — «—» с подсказкой, что нужен туннель. В списке строка протокола (п. 1) — тоже из последнего
   известного, не только после пинга.
