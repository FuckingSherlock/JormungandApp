Схемы: простые события — sub, rules, core, speed, auto

Тексты UI на английском, пояснения — на русском. Единый вид: строка времени с иконкой, заголовок, блок данных во всю ширину (только когда есть настоящие строки), Cause, кнопки (Details ▾ всегда первая). Тап по карточке ничего не открывает. Слева «сейчас» — кадры из app/build/event_shots (в кадре несколько форм: тост, уведомление, строка; нужна строка Logs — внизу кадра, прокрутка в рамке). Номера кадров — по порядку из README, у семейства sub_* часть номеров приблизительная.

  • Текст события сегодня: «<X> is unstable · N failures, excluded for M min» — режется на заголовок и две строки блока (Entry с go, Fails: число и срок исключения).
  • Запасная запись (spare: true) — info и лёгкая карточка без блока: трафик через неё не идёт, уведомления нет.
  • Return once / Don't exclude скрыты флагом до фичи «исключение на время» — в схеме их нет; когда включат, добавляются после Open.
  • Повторы по тому же адресу — счётчик ×N в строке времени.

Открытые вопросы

  • Speed: оставить цифры и в заголовке, и в блоке, или только в блоке?
  • sub/removed и sub/dead (старый журнал / мокап): рисовать ли их вообще, или оставить как есть?
  • tunNeedsAdmin: добавлять ли кнопку (например, открыть настройки режима)?
  • Кадры sub_*: номера в README группируют несколько форм в один файл; если на какой-то карточке не тот кадр — достаточно сверить по подписи внутри картинки.
