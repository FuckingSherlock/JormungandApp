# State 4: ядро на gRPC API sing-box, Speed Test, правки UI

Отправная точка для новой сессии. План и ограничения берутся из `state_3.md` (разделы «Порядок дальше»,
«Ограничения», «Решено юзером, не сделано»). Этот файл говорит, что сделано после него и с чего начинать.

## Где всё лежит
- Ветка `claude/core-mvp` влита (fast-forward) и запушена в ветку по умолчанию
  `claude/karing-fork-environment-a45c2c`. Рабочее дерево чистое.
- Тесты: `core`: `dart analyze` чисто, `dart test` 165/165. Мокап: `npm run verify` 118/118.
- jormd крутится у юзера: `dart run core/bin/jormd.dart --data core/.data-dev --lan`, данные в
  `core/.data-dev` (`ui-state.json`). Перезапускать только с разрешения юзера.

## Сделано в этой сессии
1. **3.8, переход на gRPC API service** (4ba74a2). Clash API убран из ядра и конфигов совсем. Подробно:
   `docs/core.md` (раздел про API service) и `state_3.md` п.3.8.
2. **Speed Test** (Nodes → ⋮ сервера). Ядро: `runtime.dart` `speedTest` поднимает одноразовый sing-box
   с одним сервером, `POST /api/speedtest` отдаёт NDJSON. UI: `38-speed.js`, это SpeedCard.
   - Внешнее кольцо — загрузка, внутреннее — отдача, лог-шкала до 1 Гбит/с.
   - Под кольцами Upload / Latency / Responsiveness (Low / Medium / High), статус и прогресс ~20 с.
   - Кнопка Stop / Run again. Ошибка показывается понятной фразой, под ней сырой текст sing-box.
   - Мок `12-backend.js` ведёт себя как реальность: sing-box меряет загрузку и отдачу **одновременно**,
     фазы 1/2 в прогрессе чередуются.
   - Проверено вживую: «RU-SPB ➡️ Германия» дал ~55/80 Мбит/с. Ошибка юзера (TLS handshake timeout к
     mensura.cdn-apple.com) была разовой, сервер не отвечал. Многие прямые DE/NL с ПК по TCP недоступны.
   - Пресеты `speed-test`, `speed-done`, `speed-fail`. Доки: `connect-model.md` «Speed Test сервера».
3. **Правки UI:**
   - Пинг в процессе рисуется крутилкой. Отступы блока нод выровнены, зазор протокол↔пинг уменьшен.
   - В цепочках метка подписки убрана из строк серверов, если источник один (`mixedSources`).
   - Баг «при 2 профилях нельзя поменять вход и выход цепочки» исправлен: тап по занятому концу
     («used as exit · tap to swap») вызывает `swapChainEnds()`.
   - Route: убрана внутренняя рамка вокруг серверов развёрнутой строки, серверы выровнены по подсказке
     (0b23af4).
4. Решения юзера: SSE не делаем; UDP/NAT (STUN) под вопросом; группировку в профилях пока не трогать
   («пока оставь»).

  зовёт `liveApply` при моке). Повтор проходит, причину не искали.
